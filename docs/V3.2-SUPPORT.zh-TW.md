# 七日殺（7 Days to Die）V3.2 支援版（非官方）

> **這是非官方的相容版本**，原作者沒有製作、審閱或背書。
> ServerKit 的程式碼全部出自原作者與貢獻者（MIT 授權）；這個分支只加了下面列出的小修正。
> 背景：[issue #70](https://github.com/IceCoffee1024/7DaysToDie-ServerKit/issues/70)（有人問「能用在 3.0 嗎？」——當時不行）。

## 這是什麼

官方 ServerKit **Pro3.2** 版支援的遊戲版本是 **V2.4 ～ V2.6**。
遊戲升到 V3.x 後，網頁後台起不來，`ty-gi` 等指令也會報錯
（`Field not found: ItemValue.None`），原因是遊戲內部的程式介面改了。

這個分支 `v3.2-compat` 是官方 Pro3.2 原始碼（commit `86c3be4`）加上幾個修正，讓它**能對《七日殺》V3.2.0（b10）編譯並執行**。

## 改了什麼

| 修改 | 內容 |
|---|---|
| 對 V3.2.0 b10 重新編譯 | 適配 12 組被改名或移除的遊戲介面（方塊位置、領地石判斷、拾取實體、玩家資料存檔、背包型別、睡眠區／商人區、預製建築清單、區塊快取、語言字典…）。完整清單寫在 commit 訊息裡。 |
| 拿掉沒用到的 TFP WebServer 參考 | V3.x 的專用伺服器已經沒有 `TFP_WebServer`。 |
| 修正翻譯讀取 | V3.2 在遊戲的 `Localization.txt` 中間多了一欄 `KeepLoaded`。ServerKit 原本用「第幾欄」讀語言，結果要繁體中文拿到簡體、要英文拿到空白（影響商店、抽獎、發物品訊息裡的物品名稱）。現在改成照欄位名稱找。 |
| 不再追蹤遊戲的 DLL | 遊戲的 DLL 屬於 The Fun Pimps，所以不放在這個倉庫。請用 `scripts/sync-7dtd-binaries.sh` 從自己的伺服器複製（見「從原始碼編譯」）。 |

## 測試到什麼程度

| 檢查項目 | 結果 |
|---|---|
| 對 V3.2.0 b10 編譯 | 0 個錯誤 |
| 靜態比對：DLL 引用到的每個遊戲型別／成員，在 V3.2.0 都存在且簽名相同 | 568 ／ 568，缺少的型別 0 |
| 實際伺服器（七日殺 V3.2.0 b10、專用伺服器、Linux） | 2026-10-03 起在一個**含這些相同修正、另加維護者自己功能的私人版本**上運作。真人在線驗證過：發物品、聊天指令、積分／簽到、商店、抽獎、傳送。只做過自動化 API 檢查：領地石保護、區塊重置保護、商人保護區。 |
| Release 上發布的那顆 DLL | 已照上面方式編譯與靜態比對。**單獨**在實際伺服器上跑過這件事**還沒有**。 |

沒測過的：V3.2.0 b10 以外的遊戲版本、Windows 伺服器、你可能用到的每一項功能。壞了請開 issue 告訴我們。

## 安裝（使用編好的 DLL）

這個倉庫沒有網頁前端，前端在官方發布包裡。所以做法是：先裝官方包，再換掉其中一個檔案。

1. 從[官方 Releases](https://github.com/IceCoffee1024/7DaysToDie-ServerKit/releases/tag/Pro3.2) 下載 `TianYi-ServerKit.Pro3.2.for.game.v2.4-2.6.zip`，把裡面的 `TianYiSdtdServerKit` 資料夾放進伺服器的 `Mods` 資料夾（照壓縮檔裡的「Installation tutorial.txt」做）。第一次用的話，先開一次伺服器，並照該教學設定網頁後台的埠與帳號。
2. 確認 `Mods/0_TFP_Harmony` 存在，ServerKit 需要它。我們的 V3.2 測試伺服器原本沒有這個資料夾，是從 V2.x 專用伺服器的安裝複製過來的，在 V3.2 上載入正常。標準的 V3.2 安裝有沒有附它，我們不確定。
   教學裡還列了 `TFP_CommandExtensions`、`TFP_MapRendering`、`TFP_WebServer`、`Xample_MarkersMod`。我們的 V3.2 測試伺服器上一個都沒有，網頁後台照樣能啟動（V3.x 已經沒有 `TFP_WebServer`）。
3. **先關閉伺服器。**
4. 備份 `Mods/TianYiSdtdServerKit/SdtdServerKit.dll`，再用這個 fork 的 Release 裡的 `SdtdServerKit.dll` 取代它。
5. 開啟伺服器，照平常方式打開網頁後台。

要還原：關閉伺服器，把原本的 DLL 放回去即可。

## 從原始碼編譯

需要：.NET SDK 8 以上（專案目標是 `net48`；我們是在 Linux 用 .NET 8 SDK 編的——Windows 理論上一樣能編，但我們沒試過），以及一份 **V3.2** 專用伺服器的安裝資料夾（用來複製遊戲 DLL）。

```bash
git clone -b v3.2-compat <本倉庫網址>
cd 7DaysToDie-ServerKit
bash scripts/sync-7dtd-binaries.sh "/path/to/7 Days to Die Dedicated Server"
dotnet build src/SdtdServerKit.csproj -c Release
# 產出：src/bin/TianYiSdtdServerKit/SdtdServerKit.dll
```

Windows 沒有 bash：把 `7DaysToDieServer_Data\Managed` 裡的 `Assembly-CSharp`、`Assembly-CSharp-firstpass`、`LogLibrary`、`UnityEngine.CoreModule`、`UnityEngine.AnimationModule`、`0Harmony`、`Noemax.GZip`（都是 `.dll`）複製到 `src\7dtd-binaries`，再跑同一行 `dotnet build`。

## 已知差異與限制

- **只適用 V3.x。** 這版用到 V2.4 ～ V2.6 沒有的介面（對 V2.6 做靜態比對會出現不符）。如果你用 V2.6，請繼續用官方版本。
- **跟官方發布的 DLL 有一點不同。** 官方發布的 DLL 並不是完全從公開原始碼編出來的（例如我們發現它多一條 `ty-tpa` 指令、少數字串不同），所以用這個分支編出來的 DLL 不含那些額外內容。
- 網頁前端不在這個倉庫裡，要用官方發布包裡的。
- 只在 V3.2.0 b10 測過。
