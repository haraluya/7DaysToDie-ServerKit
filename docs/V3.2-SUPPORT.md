# 7 Days to Die V3.2 support (unofficial)

> **This is an unofficial compatibility build.** It is not made, reviewed or endorsed by the original author.
> All of the ServerKit code is the work of the original author and contributors (MIT License); this branch only adds the small fixes listed below.
> Background: [issue #70](https://github.com/IceCoffee1024/7DaysToDie-ServerKit/issues/70) ("is this compatible with 3.0?" — it was not).

## What this is

The official ServerKit **Pro3.2** release targets game versions **V2.4 – V2.6**.
On 7 Days to Die V3.x the web panel does not start and commands such as `ty-gi` fail
(`Field not found: ItemValue.None`), because the game's internal API changed.

This branch, `v3.2-compat`, is the official Pro3.2 source (commit `86c3be4`) plus a few fixes, so that it **compiles and runs against 7 Days to Die V3.2.0 (b10)**.

## What was changed

| Commit | What |
|---|---|
| Recompile for V3.2.0 b10 | 12 renamed / removed game APIs adapted (block position of `BlockChangeInfo`, land-claim detection, entity pickup, player data saving, bag type, sleeper / trader volumes, prefab list, chunk cache, localization dictionary, …). The full list is in the commit message. |
| Drop the unused TFP WebServer reference | The V3.x dedicated server no longer ships `TFP_WebServer`. |
| Fix translation lookup | V3.2 inserted a `KeepLoaded` column into the game's `Localization.txt`. ServerKit read columns by position, so Traditional Chinese returned Simplified Chinese and English returned empty text (item names in the store, lottery and give-item messages). It now looks columns up by name. |
| Stop tracking game assemblies | The game DLLs belong to The Fun Pimps, so they are not in this repository. Use `scripts/sync-7dtd-binaries.sh` to copy them from your own server (see "Build from source"). |

Not tested: any game version other than V3.2.0 b10; Windows servers; every feature you might use. Please open an issue if something breaks.

## Install (use the compiled DLL)

This repository does not contain the web front-end; it comes with the official release package. So you install the official package first and then swap one file.

1. Download `TianYi-ServerKit.Pro3.2.for.game.v2.4-2.6.zip` from the [official releases](https://github.com/IceCoffee1024/7DaysToDie-ServerKit/releases/tag/Pro3.2). Put the `TianYiSdtdServerKit` folder inside it into your server's `Mods` folder (see the "Installation tutorial.txt" in the zip). If you have not run it before, start the server once and set the web panel port / account as that tutorial describes.
2. Make sure `Mods/0_TFP_Harmony` exists. ServerKit needs it. Our V3.2 test server did not have this folder, so we copied it from a V2.x dedicated server install; it loads fine on V3.2. We do not know whether a stock V3.2 install ships it.
   The tutorial also lists `TFP_CommandExtensions`, `TFP_MapRendering`, `TFP_WebServer` and `Xample_MarkersMod`. None of them were present on our V3.2 test server and the web panel still started (`TFP_WebServer` no longer exists in V3.x).
3. **Stop the server.**
4. Back up `Mods/TianYiSdtdServerKit/SdtdServerKit.dll`, then replace it with the `SdtdServerKit.dll` from this fork's Release.
5. Start the server and open the web panel as usual.

To roll back, stop the server and put the original DLL back.

## Build from source

Requirements: .NET SDK 8 or newer (the project targets `net48`; we built it on Linux with the .NET 8 SDK — Windows should work the same way but we have not tried it) and a **V3.2** dedicated server install to copy the game assemblies from.

```bash
git clone -b v3.2-compat <this repository>
cd 7DaysToDie-ServerKit
bash scripts/sync-7dtd-binaries.sh "/path/to/7 Days to Die Dedicated Server"
dotnet build src/SdtdServerKit.csproj -c Release
# output: src/bin/TianYiSdtdServerKit/SdtdServerKit.dll
```

Windows without bash: copy `Assembly-CSharp`, `Assembly-CSharp-firstpass`, `LogLibrary`, `UnityEngine.CoreModule`, `UnityEngine.AnimationModule`, `0Harmony` and `Noemax.GZip` (`.dll`) from `7DaysToDieServer_Data\Managed` into `src\7dtd-binaries`, then run the same `dotnet build`.

## Known differences and limits

- **Only for V3.x.** This build uses APIs that do not exist in V2.4 – V2.6 (a static check against V2.6 reports mismatches). If you are on V2.6, keep using the official release.
- **Slightly different from the official release DLL.** The official release is not built exactly from the public source (for example, we saw an extra `ty-tpa` command and a few different strings in it), so a DLL built from this branch does not contain those extras.
- The web front-end is not part of this repository; it comes from the official package.
- Tested on V3.2.0 b10 only.
